# RLSD math baseline

`train.rlsd.train_rlsd` implements the credit weighting in
[Self-Distilled RLVR, v2](https://arxiv.org/html/2604.03128v2), within the
repository's TRL GRPO pipeline. It supports three PI sources:

| `--pi-mode` | Teacher-only context |
| --- | --- |
| `answer` | Gold final answer, using the shared answer-PI wrapper |
| `hint` | Default cached hints generated by the base student |
| `hint_trained` | Cached hints from an explicitly identified trained generator |

The policy always samples from question-only prompts. The trained hint generator
is used to prepare the cache, not loaded as the scoring teacher. In every arm,
the scoring teacher starts from the student model and is refreshed periodically.

## Objective and defaults

For group-normalized verifier advantage A, compute on the sampled student tokens:

```text
delta_t = stop_gradient(log p_teacher(token | question, PI, prefix)
                        - log p_current_student(token | question, prefix))
weight_t = clip(exp(sign(A) * delta_t), 1 - epsilon_w, 1 + epsilon_w)
advantage_t = A * ((1 - lambda) + lambda * weight_t)
```

The inherited GRPO clipped policy-ratio objective consumes these advantages.
Its old-policy denominator is separate from the current student used in delta.
No extra distillation loss, critic, or post-weighting normalization is applied.
Zero-advantage groups remain zero. EOS tokens follow GRPO's completion mask.

Defaults are lambda 0.5, linear decay to zero after 50 completed optimizer
updates, evidence clipping 0.2, and hard teacher refresh every 10 updates.
Update 1 uses lambda 0.5; update 51 uses zero. A refresh after update 10 affects
update 11 onward. Refreshes stop once the mixing schedule reaches zero.
`--rlsd-decay-steps 0` keeps lambda constant; `--rlsd-lambda 0` is the matched
GRPO control, with teacher scoring bypassed.

Other defaults: learning rate 1e-6, constant LR, group size 8, 200 updates,
gradient accumulation 16, batch size 1, 8192 completion tokens, temperature 1,
top-p 1, top-k disabled, no reference KL, policy clipping 0.2/0.28, DAPO token
normalization. DAPO and the shared math prompt are repository adaptations;
this is not an exact reproduction of the paper's multimodal experiment.

Both scoring forwards use unpadded sequences and chunked FP32 log-probability
reductions. The current-student scoring pass is separate from its gradient-bearing
GRPO forward, keeping the base loss unchanged and matching teacher numerics.
Thus the active phase adds **two no-gradient forwards**, not just one teacher
forward. They run before the policy loss forward to limit activation memory.
Both are skipped when lambda reaches zero. A frozen teacher weight copy remains
resident. Full-model single-GPU and ordinary DDP are supported; PEFT, FSDP,
DeepSpeed, Liger, auxiliary losses, and rollout reuse across optimizer updates
are rejected by this initial implementation. GPU verification covers single GPU.

## Training

Answer PI:

```sh
CUDA_VISIBLE_DEVICES=4 .venv/bin/python -m train.rlsd.train_rlsd \
  --model Qwen/Qwen3-1.7B --dataset deepmath --pi-mode answer
```

Default hints:

```sh
CUDA_VISIBLE_DEVICES=4 .venv/bin/python -m train.rlsd.train_rlsd \
  --model Qwen/Qwen3-1.7B --dataset deepmath --pi-mode hint
```

Selected trained hints: t0.7_g6 LoRA checkpoint-80.

```sh
CUDA_VISIBLE_DEVICES=4 .venv/bin/python -m train.rlsd.train_rlsd \
  --model Qwen/Qwen3-1.7B --dataset deepmath --pi-mode hint_trained \
  --hint-generator-model /mnt/data/ujan/self-distill/outputs/hint_gen/Qwen3-1.7B/deepmath_t0.7_g6_lora_r16/checkpoint-80 \
  --hint-cache data/pi/hint/deepmath/Qwen3-1.7B-t0.7_g6_lora_r16-checkpoint-80 \
  --output-dir /mnt/data/ujan/self-distill/outputs/rlsd/Qwen3-1.7B/deepmath_hint_trained_t0.7_g6_step80
```

Generator identity must exactly match cache provenance. A default hint run may
use an explicit `--hint-cache`, but it must identify the base model as generator.
Repeat with the 4B student and its own caches; the selected 1.7B generator is not
silently substituted for 4B. Output directories for trained hints otherwise
include a digest of the generator identity to prevent collisions.

For a matched GRPO control, repeat any command with `--rlsd-lambda 0` and a
different output directory. Keep the same PI/data source so the rows, filtering,
sampling, optimizer, and normalization match exactly. File this control under
`--algo grpo` with a distinguishing `--run` label when evaluating.

The answer arm uses the training dataset; hint arms use their respective caches.
The existing 1.7B default and selected trained caches contain 3964 and 19876 rows,
respectively, before length filtering. Equal `--max-samples` does not ensure
matched question identities across these sources. Compare each arm with its
matched control, or prepare matched caches before attributing cross-arm differences
solely to PI. Counts and the ordered dataset content hash are saved in metadata.

## Checkpoints and evaluation

Every checkpoint includes `rlsd_teacher.pt` with frozen weights, teacher sync
step, and checkpoint step. Resume restores the actual stale teacher, not the
current policy or base model. `run_meta.json` strictly checks PI/cache identity,
dataset content/order, schedule, batch configuration, world size, and optimizer
settings. Missing teacher state or metadata is an error. Resume by repeating the
original command and adding `--resume-from-checkpoint PATH`; `--max-steps` is the
total budget and may be increased. An existing run directory requires explicit
resume. `final/` is a student export for inference, not a resumable checkpoint.

```sh
CUDA_VISIBLE_DEVICES=4 .venv/bin/python -m eval.run_eval_checkpoints \
  --model-dir /mnt/data/ujan/self-distill/outputs/rlsd/Qwen3-1.7B/deepmath_answer \
  --algo rlsd --model_name Qwen3-1.7B --train_dataset deepmath \
  --variant answer --dataset aime24 --n 16 --k 1 8 16
```

Use variants `hint` and `hint_trained`, plus a generator-specific `--run` label
when comparing multiple trained generators. Evaluation provides no PI to the
student. Normal result-overview discovery includes the new algorithm.

Training logs retain GRPO reward, entropy, length, clipping, and zero-reward-variance
metrics. `rlsd/` adds mixing strength, paired-scoring time, evidence differences,
effective multipliers, and evidence clipping fractions, split by positive and
negative advantages. Empty sign subsets are excluded from diagnostic means.

## Tests and GPU smoke

```sh
.venv/bin/python -m unittest tests.test_rlsd tests.test_train_sdft tests.test_eval_checkpoints
CUDA_VISIBLE_DEVICES=4 HF_HUB_OFFLINE=1 VLLM_USE_V2_MODEL_RUNNER=0 \
  OMP_NUM_THREADS=1 TOKENIZERS_PARALLELISM=false \
  .venv/bin/python -m tests.smoke_rlsd --pi-mode answer \
  --output-dir results/debug/rlsd_smoke/answer
```

Repeat the smoke with `hint` and `hint_trained`, using distinct output directories.
It uses real cached PI, two samples per group, 64 completion tokens, four updates,
teacher refresh at update 2, and weighting decay after update 3. Synthetic
alternating verifier rewards ensure nonzero advantages of both signs; these
results measure implementation correctness, not math accuracy.

To exercise resume, repeat the smoke into an empty output directory with
`--resume-from-checkpoint results/debug/rlsd_smoke/answer/checkpoint-1`.
The smoke checks nonzero policy gradients, absent teacher gradients, active
weight bounds, the zero-mixing phase, and saved teacher sync state.

Validation completed on 2026-10-09 with Qwen3-1.7B on single H100 GPUs:

- All three vLLM smoke runs passed: `results/debug/rlsd_smoke/answer_v2`,
  `hint_v2`, and `hint_trained`, each with a `smoke_summary.json`.
- Resuming answer checkpoint 1 reproduced the uninterrupted final student
  (310 tensors) and teacher (311 tensors) bitwise. Evidence is saved in
  `results/debug/rlsd_smoke/resume_comparison.json`.
- The production CLI completed a one-step trained-hint run with the real math
  verifier in `results/debug/rlsd_smoke/cli_hint_trained`. Its short responses
  received zero reward, so the synthetic smoke supplies the gradient check.
- The affected unit tests and Ruff checks passed. Full training and long-context
  memory usage have not been evaluated by these short smoke runs.
