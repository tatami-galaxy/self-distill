1. This codebase has LLM post training experiments with multiple algorithms : grpo, ppo, on policy distillation, op policy self distillation, sft. The ppo code is custom, built on top of TRL's GRPOTrainer for RLVR tasks like math in our case. opsd has mostly SDFT ([https://arxiv.org/html/2601.19897](https://arxiv.org/html/2601.19897)) based experiments and also some self-teacher training experiments. We are also doing some teacher analysis experiments and visualizations in eval.



2. Self-distillation is a useful framework but it does not work particularly well for reasoning models. Take a look at these papers : [https://arxiv.org/html/2607.05184v1](https://arxiv.org/html/2607.05184v1) , [https://arxiv.org/html/2603.24472v4](https://arxiv.org/html/2603.24472v4). Essentially, the PI conditioned self-teacher penalises exploration in the student among other things like critiquing style etc. instead of only reasoning.  

One way to go about solving this is a privileged value function in the PPO formulation : [https://arxiv.org/html/2608.16739v1](https://arxiv.org/html/2608.16739v1) . train_ppo_pi is roughly in this direction. The idea is to not do self distillation but instead have the value function learn how to use PI to be a better critic. 

However this throws away the self distillation advantage we get for free at init. Instead we want the advantage to be exactly the self-distillation advantage at init. We then would like to correct/edit it and remove noise by regressing onto outcome rewards. This might let us get away with no (value) pretraining at all. 

To do this we can add a Q head to the self teacher. We can pass it the next token log probs of the self-teacher model. This leads us use the self distillation advantage at init. We can fit Q using n-step returns or a GAE style lambda return or some other way. Since Q is initally logprobs and we are regressing onto binary outcome rewards, there is a scale mismatch we will have to think about. We'll also need to think about what exactly we want the learned Q to represent. But before that, first check the derivation of this formulation at docs/derivations.md and see if its correct.
